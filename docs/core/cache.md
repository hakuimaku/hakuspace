# Disposable cache

HakuSpace-owned cache lives under `${XDG_CACHE_HOME:-$HOME/.cache}/hakuspace`.
Unset or empty `XDG_CACHE_HOME` uses `$HOME/.cache`; the `hakuspace` namespace is
always appended. No additional environment/configuration file is required.

Bash consumers source `haku_cache.sh` and use `HAKUSPACE_CACHE_DIR`. Python
consumers use `haku_cache.cache_root()`. Resolving these paths creates nothing.
Hikai's WallpaperService delegates Open Cache to the wallpaper backend, which
creates and opens the same directory used by cache generation.

Everything inside this directory is disposable and can be regenerated from
original media or installed icons. Deleting it preserves wallpaper selection,
desktop icon positions, preferences and original files. A missing video proxy
still follows the user's preparation policy. Configuration remains in
`~/hakucfg` and application config directories; persistent selections and layout
use the [state system](state.md). Session-only sockets and process files retain
their runtime directory contracts.

## Path audit

The audit covers tracked source, hidden configuration, scripts, QML, Rasi,
Python, documentation, fixtures and tooling. Destinations below are relative to
the canonical cache root unless stated otherwise.

| Discovered path or reference | Classification | Destination or retained behavior |
| --- | --- | --- |

| `~/.cache/walpaper_box_gen.jpg` | HakuSpace cache | `wallpaper/walpaper_box_gen.jpg` |
| `~/.cache/backdrop.jpg` | HakuSpace cache | `wallpaper/backdrop.jpg` |

| `~/.cache/*` in `clean.sh` | Intentional generic cache cleanup | Remains a global cleanup command; its documentation retains that meaning |
| `.cache/` and `*.cache` in `.gitignore` | Repository ignore patterns | Unchanged; no runtime path is created |

| Temporary `PYCACHE_DIR` in repository validation | Runtime/transient tooling | Remains a private `mktemp` directory, removed after compilation |
| `XDG_CACHE_HOME` and temporary `.cache` homes in tests/profiling | Isolated fixtures | Retained as test inputs; expectations for generated assets use the namespace |
| Old paths mentioned in assertions/migration tests and this audit | Documentation/test fixtures | Retained to detect regressions and exercise upgrades |
| Wallpaper option comments and wallpaper documentation | Documentation | Updated to the XDG-aware rule and persistent state terminology |

The `walpaper_*` spelling was a typo shared by the old producer and Rasi
consumers. It is retained as a compatibility filename inside the new namespace;
renaming it provides no cache isolation benefit.

Rofi reads `~/.local/state/hakuspace/theme/rofi-wallpaper.rasi`, generated by the
existing theme renderer and wallpaper setter. Like the other generated theme
configuration, it contains references only: escaped absolute URLs for wide and
box images. The image data itself lives in cache. Neither the current working
directory nor a relative path from the Rasi file determines the cache location.

Legacy persistent entries are imported before state initialization or direct
Classic/Hikai access. Publication is atomic and does not overwrite existing
canonical state. Conflicting legacy bytes are retained in the existing private
state migration archive. New code never writes a legacy pointer. Disposable old
assets are left unused; the refactor does not sweep unrelated cache contents.

## Regression checks

`python3 tools/checks/cache_paths.py` scans production source and scripts,
including new files. Exact exceptions cover only the shared fallback helpers,
read-only legacy state import, shared desktop thumbnail reads and generic cache
cleanup. Documentation, tests and isolated profiling homes are not production
cache writers. The check runs in `tools/checks/repo_check.sh`.

`python3 tests/config/cache/test_paths.py` checks default/empty/custom XDG roots,
state preservation, conflict handling, unsafe legacy symlinks, Classic generation
and resume, taskbar extraction/cache hits, Classic video thumbnails, real Rofi
theme parsing and Hikai cache opening. Fixtures cover spaces and quotes in paths.
Wallpaper component tests additionally exercise real ImageMagick/FFmpeg output
and native commit failure preservation.

After changes, repeat the tracked-file audit and enforce its classifications:

```bash
git grep -n -I -E '(\.cache|XDG_CACHE_HOME|CACHE_DIR|current_wallpaper|taskbar_icons|taskbar_icon_cache|wall?paper_.*_gen)'
python3 tools/checks/cache_paths.py
python3 tools/checks/state_schema.py
```
